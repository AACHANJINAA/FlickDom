# FlickDom (플릭덤) - 상세 개발 및 기획 플랜

기존의 요약된 기획(README)을 바탕으로, **"재미가 최우선(Fun is the first feature)"**이라는 게임 디자인 원칙과 **"코어 루프의 빠른 프로토타이핑"** 원칙을 적용하여 더욱 구체화된 기획 및 구현 플랜입니다.

## User Review Required

> [!IMPORTANT]
> 게임의 조작감(Game Feel)과 시각적 피드백(Juice)에 초점을 맞춘 추가 기획이 포함되어 있습니다. 특히 '물리 충돌 타격감'과 '카메라 연출' 부분을 중점적으로 검토해 주세요.

## Open Questions

> [!WARNING]
> 기획의 세부적인 부분을 확정하기 위해 다음 사항들에 대한 논의가 필요합니다.
> 1. **점령 카드 판정 규칙:** 2칸/3칸/4칸 패턴이 5x5 보드판의 **아무 위치**에서나 모양만 맞으면 달성되는 것인지, 아니면 카드가 지시하는 **특정 절대 좌표**에서 달성해야 하는 것인지 명확히 해야 합니다. (현재는 '아무 위치에서 모양만 일치하면 됨'으로 가정하고 플랜을 세웠습니다.)
> 2. **토큰 물리 속성 (Physics Material):** 알까기 토큰들이 당구공처럼 통통 튀어야 할지(탄성 높음), 아니면 바닥 마찰이 강해서 묵직하게 밀려나야 할지(마찰력 높음) 방향성을 정해야 합니다.

## 🎮 1. 코어 플레이 루프 & 3C (Character, Control, Camera) 고도화 기획

### 1-1. Control (조작 & 타격감 극대화)
알까기의 손맛(Juice)을 살리기 위해 입력 단계에서 확실한 피드백을 줍니다.
- **궤적 표시 (Trajectory Line):** 마우스로 드래그하여 뒤로 당길 때, 예상 날아갈 방향과 힘의 크기를 선으로 시각화합니다.
- **게이지 인디케이터:** 최대 당김 거리에 도달하면 빨간색으로 점멸하거나 UI 이펙트를 주어 시각적 긴장감을 줍니다.

### 1-2. Camera (시점 전환 연출)
게임 상태에 따라 극적인 연출을 줍니다.
- **Ready / Placement (2D 분할):** 보드판을 정확히 수직(Top-down)에서 내려다보는 정적 카메라.
- **Flicking (3D 45도 쿼터뷰):** 내 턴이 시작되면 카메라가 부드럽게 45도 측면으로 스윕(Sweep)하며 내려와 몰입감을 높입니다.

### 1-3. Feedback (충돌 & 이펙트 - Juice)
- **충돌 타격감:** 토큰끼리 부딪힐 때 가벼운 카메라 쉐이크(Camera Shake)와 함께 파편이 튀는 파티클 효과(VFX) 발생.
- **영토 점령 피드백:** 5x5 맵에 내 토큰이 성공적으로 안착하면, 해당 그리드 바닥이 내 팀 색상으로 '네온사인'처럼 부드럽게 빛나는 효과 부여.

## 💻 2. 구현 계획 (Implementation Steps)

### Phase 1: 코어 루프 프로토타이핑 (이번 주 목표)
**가장 먼저 "튕기고, 부딪히고, 멈춘다"는 핵심 재미를 완성해야 합니다.**
- 궤적 시각화 시스템 추가 (당기는 방향의 반대 방향으로 궤적 라인 생성)
- 토큰의 탄성(Bounciness)과 마찰력(Friction) 물리 속성 튜닝
- 충돌 강도(Velocity)에 비례하여 파티클 시스템 재생 및 사운드 출력 이펙트 추가

### Phase 2: 보드 맵 로직 & 카메라 트랜지션
- 2개의 가상 카메라(TopDown, Isometric)를 배치하고, 게임 상태 변경 이벤트에 맞춰 카메라 시점을 부드럽게 전환
- 물리적으로 멈춘 위치를 기반으로 5x5 논리 인덱스로 좌표 매핑
- 만약 토큰이 두 칸에 걸쳤을 경우, 플레이어가 직접 원하는 칸을 선택할 수 있는 UI 로직 및 데이터 동기화 구현

### Phase 3: 점령 카드 시스템 (Card Pattern Matching)
- 2D 배열(int[5,5])에서 특정 패턴(2칸, 3칸, 4칸 테트리스 모양 등)이 존재하는지 검사하는 행렬 스캔 알고리즘 개발
- 패턴 매치 성공 시 카드 획득 처리 및 다음 난이도(Easy -> Normal -> Hard) 카드 오픈 로직 구축

## 🧪 3. 검증 계획 (Verification Plan)

### 수동 플레이테스트 (Playtest)
1. **마찰/탄성 테스트:** 드래그 힘 수치를 다양하게 바꿔보고, 물리 매터리얼의 마찰력을 조절하며 "가장 찰지게 맞는" 값을 찾습니다. (이 과정은 코드가 아닌 직접 플레이하며 감각적으로 찾아야 합니다.)
2. **패턴 매칭 검증:** 임의로 5x5 배열 데이터를 조작하여, 하드코딩된 'L자 모양', 'I자 모양' 등의 패턴이 정확히 매치되어 카드가 획득되는지 콘솔 로그로 확인합니다.
